# Sub2API 小说创作工作台开发任务

**任务编号**：`PINOVEL-NOVEL-WORKBENCH-1`  
**优先级**：P0（普通用户主产品体验）  
**编制日期**：2026-07-23  
**涉及仓库**：`sub2api`（主要开发）、`PiNovelStudio`（生成链路契约与联调）  
**前置任务**：`PINOVEL-SUB2API-INTEGRATION-1` 代码链路  
**目标**：普通用户登录后直接进入完整的小说创作工作台，在一个界面内完成作品设定、世界观、角色、大纲、章节管理、正文编辑、AI 规划和章节生成；余额不足时引导充值，并可查看脱敏的消费记录。

> 参考产品：[炼字工坊](https://lianzigongfang.com/) 的公开产品信息。只参考“一站式小说工作台、设定 → 大纲 → 章节、知识库一致性、编辑器、自动保存”等产品思路，不复制其品牌、文案、素材、页面代码或非公开设计。

---

## 一、当前问题与开发结论

### 1. 当前已具备

- `/novel` 项目列表和 `/novel/:id` 项目页面。
- CreativeConstitution、世界观、角色档案、故事大纲、作者风格、ChapterSeed 等文档存取。
- 章节目录和章节详情读取。
- 受限 AI 大纲规划。
- `novel_generate_chapter` 唯一章节生成入口。
- 生成前费用估算、余额预占、逐次模型调用结算、余额不足阻断、取消任务和生成进度。
- 输入安全检查、输出防泄露检查、租户隔离。

### 2. 当前主要缺口

- 普通用户登录后默认进入通用 `/dashboard`，不是小说创作页面。
- `backend_mode` 会彻底阻断普通用户；`simple` 模式会跳过计费，两者都不能作为小说产品模式。
- 普通用户仍看到 API Key、渠道、订阅、批量图片、兑换码、推广等非小说功能。
- 现有项目页采用“资料/助手/章节/生成/反馈”标签切换，创作资料和正文相互割裂。
- 角色和大纲主要是 Markdown 大文本，不适合角色卡、卷章树和结构化编辑。
- 章节缺少面向用户的手工保存、版本历史、恢复和稳定自动保存接口。
- 文档版本能力存在于服务层，但尚未形成完整的用户 API 和前端恢复界面。
- 用户只能查看单个生成任务，缺少小说生成/AI 规划消费历史列表。
- 小说前端缺少专项单元测试与完整 E2E。

### 3. 产品决策

新增独立的 **小说用户门户模式**，建议配置名：

```text
user_portal_mode = standard | novel
```

- `standard`：保留原 Sub2API 普通用户门户。
- `novel`：普通用户只使用小说创作、充值、订单、消费记录和个人资料。
- 管理员继续使用完整管理后台。
- 小说门户模式仍使用 `run_mode=standard` 的余额和计费能力。
- 禁止用 `backend_mode` 或 `run_mode=simple` 模拟小说门户模式。

## 二、目标用户流程

```text
注册/登录
  → 小说项目列表（无项目则显示新建向导）
  → 进入项目工作台
  → 完善作品定位、世界观、角色和大纲
  → AI 助手协助规划（收费，用户确认后执行）
  → 选择/创建章节种子
  → 生成前检查与费用确认
  → novel_generate_chapter 统一主链路
  → 查看、手工修改和保存章节
  → 继续下一章
  → 查看消费记录或余额不足时充值
```

### 登录落点

- 普通用户：默认进入 `/novel`。
- 普通用户通过带有安全 `redirect` 的登录链接进入时，允许返回对应小说页、充值页或订单页。
- 管理员：默认进入 `/admin/dashboard`。
- 普通用户访问 `/`、`/dashboard` 时，在小说门户模式下统一重定向 `/novel`。

## 三、目标页面与信息架构

### 1. 普通用户全局导航

小说门户模式下只显示：

1. 小说创作
2. 充值
3. 消费记录
4. 订单
5. 个人资料
6. 退出登录

隐藏并禁止普通用户访问：

- API Key 管理
- 模型、Provider、渠道和渠道状态
- 通用技术用量页和 token 明细
- 批量图片
- 订阅配置
- 兑换码和推广
- 自定义菜单
- 管理员 Prompt、Trace、审计和模型路由

必须同时实施菜单隐藏、前端路由守卫和后端用户 API 白名单，不能只隐藏菜单。

### 2. `/novel` 小说项目首页

页面包括：

- 最近创作项目。
- 全部项目列表，支持标题搜索、更新时间排序、状态筛选。
- 新建小说向导。
- 项目卡展示：书名、类型、简介、章节数、总字数、最后编辑时间、最近生成状态。
- 快速操作：继续创作、项目设置、归档、删除。
- 顶栏展示可用余额和“充值”按钮。
- 没有项目时，以“创建第一部小说”为唯一主操作，不显示空仪表盘。

### 3. `/novel/:id` 小说创作工作台

桌面端采用三栏工作区，可折叠左右栏：

```text
┌─────────────────────────────────────────────────────────────────┐
│ 返回作品  书名  保存状态/字数        可用余额 充值 生成状态 账户 │
├──────────────┬──────────────────────────────┬───────────────────┤
│ 作品结构      │ 主编辑区                       │ AI 创作助手        │
│              │                              │                   │
│ 作品设定      │ 根据左侧选择显示：             │ 当前上下文          │
│ 世界观        │ - 表单/卡片编辑器              │ 快捷规划动作        │
│ 角色          │ - 大纲树与节点编辑             │ 对话历史            │
│ 故事大纲      │ - 章节正文编辑器               │ 费用确认与执行      │
│ 章节目录      │ - 版本历史/预览                │ 生成进度/结果       │
│              │                              │                   │
└──────────────┴──────────────────────────────┴───────────────────┘
```

#### 顶栏

- 返回项目列表。
- 作品标题和当前编辑对象。
- 保存状态：`已保存 / 保存中 / 保存失败 / 存在冲突`。
- 当前正文或文档字数。
- 可用余额和充值入口。
- 进行中任务提示；离开页面后任务继续，重新进入可恢复进度。
- 用户菜单。

#### 左侧作品结构

固定分组：

- **作品设定**：作品定位、CreativeConstitution、作者风格。
- **世界观**：背景、地点、势力、力量体系、规则、时间线、术语。
- **角色**：主角、配角、反派和其他角色卡。
- **故事结构**：总纲、分卷、剧情线和章纲。
- **章节目录**：章节编号、标题、字数、状态和生成标记。

能力要求：

- 当前节点高亮。
- 大纲节点和章节支持拖动排序；排序必须服务端校验并原子保存。
- 支持折叠分组和快速搜索角色/章节。
- 章节状态只显示用户语言：草稿、AI 已生成、已定稿、生成中、生成失败。
- 不显示内部模型、Stage、Route、Prompt、Trace 或工具名称。

#### 中间主编辑区

- 作品设定和世界观使用结构化分区表单，保留“补充说明”Markdown 文本。
- 角色使用角色卡列表和独立编辑器。
- 大纲使用卷 → 剧情线/节点 → 章节的树形结构，右侧编辑当前节点。
- 章节使用长文本编辑器，支持标题、正文、字数、保存、版本历史和恢复。
- 章节正文支持安全 Markdown 预览，但禁止原始 HTML。
- `Ctrl/Cmd + S` 立即保存。
- 自动保存防抖建议 1 秒；保存必须带 `expected_version` 实现乐观锁。
- 版本冲突返回 409，前端提供“重新加载服务端版本”和“复制我的未保存内容”，禁止静默覆盖。
- 不把小说正文、角色档案、系统令牌或内部配置写入 LocalStorage。
- 手工编辑与保存不收费。

#### 右侧 AI 创作助手

助手只能处理小说创作，禁止 Shell、代码执行、任意文件访问、Git、任意 URL 和用户自选模型。

首期快捷动作：

- 完善作品定位。
- 补充世界观。
- 完善当前角色。
- 整理故事总纲。
- 拆分卷纲或章纲。
- 生成/完善下一章 ChapterSeed。
- 检查设定、角色和大纲之间的明显矛盾。
- 发起完整章节生成。

交互规则：

- 自动携带当前项目和当前选中对象上下文，用户不需要粘贴全部资料。
- AI 规划结果先显示预览或差异，用户点击“应用”后才写入正式资料。
- AI 不能在普通对话区直接输出章节正文。
- 章节正文必须调用 `novel_generate_chapter`，不得增加 one-shot 续写或绕过统一编排的按钮。
- AI 请求前显示预计费用或最大费用；用户确认后才发起。
- 所有 AI 对话、规划和生成都通过 Sub2API 内部计费出口。
- 用户看不到真实模型、Provider、Route、系统提示词、工具清单、token 明细或内部策略。

### 4. 生成交互

点击“生成章节”后：

1. 自动选择下一章节号，也允许用户选择已有草稿章节。
2. 运行 Preflight，缺少必填资料时显示可点击的缺失项。
3. 展示预计字数、预计费用区间、最高消费上限和当前可用余额。
4. 默认由服务端给出建议最高消费上限；可将用户自定义上限放入“高级设置”，不得超过服务端建议值。
5. 余额不足时禁用生成按钮，主操作变为“去充值”。
6. 用户确认后进行余额预占并启动生成。
7. 只显示友好进度：检查资料、准备章节、生成正文、优化风格、检查连续性、保存章节。
8. 支持取消；取消后结算已发生费用并释放未使用预占。
9. 成功后自动打开生成章节，显示本次消费和剩余余额。
10. 失败或余额耗尽时显示：已产生费用、未完成原因、充值/修改资料/重试入口。
11. 未完成正文不得保存为正式章节，不得提交长期叙事状态。

### 5. `/novel/billing` 消费记录

普通用户看到脱敏聚合账单：

- 时间。
- 类型：AI 对话、故事规划、章节生成、退款/调账。
- 作品名。
- 章节号或操作摘要。
- 状态：进行中、成功、失败、取消、已退款。
- 实际消费金额。
- 失败任务的已消费金额和已释放额度。

禁止显示：

- 模型名、Provider、Route。
- 输入/输出 token 明细。
- 内部 Stage、Prompt、工具名、Trace 和请求载荷。

支持按时间、作品和消费类型筛选，并提供充值入口。

## 四、数据模型与后端接口任务

### T1：小说门户模式和权限边界

**开发内容**：

- 增加 `user_portal_mode=novel` 配置与管理后台开关。
- 公共设置仅返回门户模式，不返回内部模型配置。
- 新增普通用户门户路由守卫。
- 后端对 JWT 普通用户采用显式 API 白名单，而不是不断增加黑名单。
- 保留认证、小说、充值、支付回调、订单、个人资料和退出接口。
- 管理员 API、内部 LLM 网关和内部 Novel Runtime 调用不受普通用户门户白名单影响。

**验收**：

- 普通用户登录默认到 `/novel`。
- 管理员登录默认到 `/admin/dashboard`。
- 普通用户直接输入 `/keys`、`/available-channels`、`/monitor` 等地址时返回 `/novel` 或 403。
- 普通用户直接调用对应用户 API 返回统一 403。
- 小说充值和扣费仍使用标准模式，未跳过余额检查。

### T2：结构化角色、世界观和大纲

现有 Markdown 文档继续兼容，但工作台需要结构化读写能力。

建议新增：

```text
novel_characters
novel_outline_nodes
novel_chapter_seeds
```

`novel_characters` 至少包含：

```text
id, user_id, project_id, name, aliases, role_type, identity,
goals, motivation, personality, abilities, relationships,
secrets, character_arc, current_state, notes, sort_order,
version, created_at, updated_at, deleted_at
```

`novel_outline_nodes` 至少包含：

```text
id, user_id, project_id, parent_id, node_type,
title, summary, narrative_goal, conflict, turning_point,
ending_hook, pov_character_id, involved_character_ids,
sort_order, version, created_at, updated_at, deleted_at
```

`node_type` 建议：`book | volume | arc | chapter`。

`novel_chapter_seeds` 至少包含：

```text
id, user_id, project_id, chapter_number, intent, must_include,
forbidden_facts, character_motives, promises, ending_goal,
status, version, created_at, updated_at
```

必须提供：

- 角色 CRUD、排序和乐观锁接口。
- 大纲节点 CRUD、移动、批量排序和乐观锁接口。
- ChapterSeed 按章节 CRUD 接口。
- 从现有 `character_profile`、`story_outline`、`chapter_seed` 文档读取兼容数据的迁移方案。
- 迁移必须可重复执行，不丢失原 Markdown；原始内容可进入补充说明字段或只读历史版本。
- 所有查询强制附加当前 `user_id`。

### T3：章节编辑、版本和恢复

新增用户接口：

```text
PUT  /api/v1/novel/projects/:id/chapters/:number
GET  /api/v1/novel/projects/:id/chapters/:number/versions
POST /api/v1/novel/projects/:id/chapters/:number/versions/:version/restore
```

要求：

- 手工创建/修改章节不调用模型、不收费。
- 请求包含 `title`、`content`、`status`、`expected_version`。
- 新增 `novel_chapter_versions`，记录手工保存、AI 生成和恢复操作的快照及来源。
- 章节状态枚举统一为 `draft | generated | final`；迁移现有 `completed/generating/failed` 口径，运行任务状态留在 generation job，不混入正文状态。
- 生成成功保存章节时创建来源为 `ai_generated` 的版本。
- 恢复历史版本本身也创建新版本，历史记录不可变。
- 删除章节采用软删除并二次确认。

### T4：文档版本接口补齐

新增：

```text
GET  /api/v1/novel/projects/:id/documents/:type/versions
POST /api/v1/novel/projects/:id/documents/:type/versions/:version/restore
```

要求：

- 复用现有 `novel_document_versions`。
- PUT 文档接口支持 `expected_version`，冲突返回 409。
- 版本响应不得包含内部 metadata。
- 前端可查看时间、版本号、变更来源和内容预览。

### T5：AI 助手会话

建议新增：

```text
novel_assistant_conversations
novel_assistant_messages
```

用户接口：

```text
GET  /api/v1/novel/projects/:id/assistant/conversations
POST /api/v1/novel/projects/:id/assistant/runs/estimate
POST /api/v1/novel/projects/:id/assistant/runs
GET  /api/v1/novel/projects/:id/assistant/runs/:runId
GET  /api/v1/novel/projects/:id/assistant/runs/:runId/events
POST /api/v1/novel/projects/:id/assistant/runs/:runId/apply
```

`intent` 必须是服务端白名单：

```text
project_positioning
worldbuilding
character_refinement
outline_planning
chapter_seed_planning
consistency_review
```

要求：

- 不接受用户传入模型、Provider、URL、工具名、系统提示词或任意能力声明。
- 服务端根据 intent 选择受限 PI 能力。
- 输入安全检查必须在余额预占之前。
- AI 返回结构化 proposal；`apply` 前校验目标对象版本，禁止静默覆盖用户刚保存的内容。
- `apply` 只修改声明的项目资料，不允许写任意路径。
- 对话与规划按实际调用结算，并进入用户脱敏消费记录。
- `chapter_generation` 不属于普通助手 intent，只能调用独立章节生成接口。

### T6：生成任务和消费历史

新增用户列表接口：

```text
GET /api/v1/novel/generations?page=&page_size=&project_id=&status=
GET /api/v1/novel/billing/summary
GET /api/v1/novel/billing/ledger?page=&page_size=&project_id=&type=&from=&to=
```

要求：

- generation 列表只返回当前用户的任务。
- ledger 聚合 `novel_generation_jobs`、AI 助手任务和 `novel_billing_adjustments`。
- 用户 DTO 使用业务类型，不返回 `internal_stage`、token、模型归属或内部 request payload。
- 管理员账本继续保留真实归属和审计能力。

## 五、前端任务拆分

### F1：路由和小说门户壳层

- 普通用户登录落点改为 `/novel`。
- 建立小说门户专用布局，移除通用 Sub2API 用户菜单。
- 管理员布局保持不变。
- 处理 `/dashboard` 和已隐藏路由的重定向。
- 顶栏全局余额组件和充值入口。

### F2：项目首页和新建向导

- 项目搜索、排序、筛选、空状态和最近项目。
- 新建向导分为：书名与类型 → 核心创意 → 基础世界观/主角 → 创建。
- 新建向导只保存用户输入；如果用户选择 AI 辅助，必须单独估价和确认。

### F3：工作台框架

- 三栏布局、可折叠侧栏、可恢复上次选中位置。
- 左侧树按需加载，长章节目录使用虚拟滚动。
- 路由 query 或子路由表达当前编辑对象，刷新页面可恢复。
- 统一 loading、empty、error、conflict 和 permission 状态。

### F4：设定、世界观、角色和大纲编辑器

- 结构化表单与补充说明。
- 角色卡新增、复制、归档、删除、排序和搜索。
- 大纲树新增、移动、删除、排序和节点详情编辑。
- 保存状态、乐观锁冲突和版本历史。

### F5：章节目录和正文编辑器

- 章节目录、状态、字数和最近更新时间。
- 正文编辑、保存、自动保存、Markdown 安全预览。
- 章节版本历史、对比预览和恢复。
- 生成完成后自动定位新章节。
- 用户修改生成稿后继续保存为新版本，保留生成原稿版本。

### F6：AI 助手和生成抽屉

- 当前上下文提示、意图快捷按钮、对话历史。
- 估价确认、余额不足、proposal 预览、差异和应用。
- 章节生成 Preflight、费用确认、进度、取消、完成和失败恢复。
- 页面刷新后恢复进行中任务。
- 不渲染原始模型错误和内部日志。

### F7：消费记录

- 余额摘要、充值按钮、消费筛选和分页列表。
- 显示任务级聚合费用，不显示技术归属。
- 失败、取消、退款状态具有明确说明。

## 六、安全与产品保护要求

1. 浏览器永远不直接访问 Novel Runtime 或模型网关。
2. 用户不能输入或覆盖模型、Provider、Route、Base URL、API Key、Prompt 模板和工具白名单。
3. 小说门户前端 DTO、日志、错误提示和生成进度不得出现模型名、内部 Stage、工具名或路径。
4. 输入安全检查必须发生在余额预占和上游调用之前。
5. 输出在保存和返回前必须经过防泄露检查。
6. 正常虚构文学内容不得被通用危险词规则粗暴误杀；保留 fiction context 策略。
7. Markdown 必须经 DOMPurify，禁止 raw HTML 和脚本事件属性。
8. 用户作品不写 LocalStorage，不进入前端埋点正文，不记录到普通应用日志。
9. 所有项目、角色、大纲、章节、版本、助手会话和账单查询强制附加当前 `user_id`。
10. 对越权 ID 返回统一 Not Found，避免枚举其他用户资源。
11. 生产构建关闭 source map，静态扫描小说用户 chunk 不得包含内部密钥、模型路由或系统 Prompt。
12. “防反向蒸馏”按可实现边界执行：核心编排、Prompt、模型路由、策略和 Trace 只存在服务端；不能承诺阻止用户从正常输出推测一般写作方法。

---

## 七、兼容与迁移要求

- 保留现有 `/novel` 和 `/novel/:id` 可用，允许增加规范子路由但不得让旧书签失效。
- 现有项目、文档和章节必须可正常打开。
- 结构化迁移先复制、后切换，迁移失败不得删除原 Markdown。
- 所有新增 migration 可重复运行或具有明确版本保护。
- 当前进行中的 generation job 不因前端升级丢失。
- 不改变 `novel_generate_chapter` 唯一生成入口。
- 不恢复 legacy Stage0-8、one-shot raw、机器文学裁判或用户自选模型。

### 3. E2E 场景

至少完成以下真实浏览器场景：

#### E2E-1 新用户首创作

```text
普通用户登录
→ 自动进入 /novel
→ 创建项目
→ 新建主角
→ 保存世界观
→ 创建总纲
→ 创建第一章种子
→ 余额不足
→ 点击充值入口
```

#### E2E-2 充值后生成章节

```text
充值成功
→ 返回项目工作台
→ 生成前估价
→ 确认生成
→ 查看实时进度
→ 生成完成
→ 自动打开章节
→ 显示本次消费和剩余余额
→ 消费记录存在对应聚合条目
```

#### E2E-3 编辑与版本恢复

```text
修改生成章节
→ 自动保存
→ 查看版本历史
→ 恢复生成原稿
→ 恢复动作创建新版本
```

#### E2E-4 安全与权限

```text
普通用户访问 /keys 和 API Key 接口 → 拒绝
用户提交提示词提取/模型探测内容 → 预占前阻断
用户访问其他用户 project/character/chapter → Not Found
小说页面和网络响应不出现模型/Provider/Route/Prompt/Trace
```

#### E2E-5 余额耗尽和取消

```text
生成中预算耗尽或用户取消
→ 不再发起下一次模型调用
→ 不保存未完成正式章节
→ 不提交长期状态
→ 已产生费用正常结算
→ 剩余预占释放
→ 页面显示充值或重新生成入口
```

## 十、明确非目标

首期不做：

- 用户选择或查看模型。
- 用户配置 API Key、Provider、Base URL 或 Prompt。
- 通用 AI 聊天机器人。
- 浏览器直接调用 PI、PiNovelStudio 或 Novel Runtime。
- AI 对话直接输出并覆盖章节正文。
- 绕过 `novel_generate_chapter` 的一键续写、局部正文生成或 one-shot 生成。
- 多人协作、公开发布、社区、投稿平台直发。
- 文件上传、URL 导入、抓取其他小说、拆书仿写。
- 封面生成、图片生成、漫剧和剧本工作台。
- 宣称能够绝对阻止用户从输出中推测任何一般性写作方法。

这些能力如需增加，应单独立项并重新评估版权、内容安全、计费和生成主链路约束。

## 十一、完成定义

只有同时满足以下条件，才能声明任务完成：

1. 普通用户登录后直接进入小说项目首页。
2. 普通用户门户中不存在 API Key、模型、渠道等技术配置入口。
3. 用户可在单一工作台完成设定、世界观、角色、大纲、ChapterSeed、章节目录和正文编辑。
4. AI 助手只能进行受限小说规划，所有正式章节通过统一生成主链路。
5. 手工编辑免费，所有 AI 请求按实际调用正确扣费。
6. 余额不足、任务取消和运行中耗尽均能正确停止、结算和恢复用户操作。
7. 用户可查看脱敏的小说消费记录。
8. 文档和章节具有自动保存、乐观锁、版本历史和恢复能力。
9. 权限、安全、租户隔离和防泄露测试全部通过。
10. 真实测试环境完成“登录 → 创建作品 → 充值 → 生成 → 编辑 → 查看消费”的端到端验收。
