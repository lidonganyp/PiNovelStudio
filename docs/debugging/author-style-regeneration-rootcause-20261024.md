# 重新生成时作者风格优化失败：根因与修复

日期：2026-10-24。范围：项目252历史任务证据、当前统一生成链路、隔离回归测试。未调用付费模型，未修改用户正文、资料、叙事状态或生产发布指针。

## 第一性原理

风格优化应当是一个有明确边界的变换：以已验证的 Agentic 初稿为事实底稿，使用作者定性风格指导调整表达，然后验证故事、事实和完整性。续写时，作者已有正文是不可编辑前缀；只有新增后缀进入优化，主程序负责拼接。生成要求、返回值校验和拼接必须使用同一个边界。

风格档案可用，不等于模型输出符合边界；模型返回了文本，也不等于重试成功。不能用扩大重试次数、关闭事实检查或把失败初稿改名为优化稿来解决问题。

## 当前代码中确定复现的缺陷

### 1. 提示词末尾三元表达式优先级错误

原代码形式为 `"事实边界" + input.continuationMode === "append" ? suffixRule : fullRule`。

JavaScript先做字符串拼接再比较，条件实际总为false。因此续写也落到“只输出优化后的完整正文”，并且丢失末尾本来要拼上的事实边界。此前测试仅检查整个提示词里存在某条规则，没有检查实际发给模型的末尾指令。

修复：给模式分支加括号，保留边界文字。测试核对实际模型请求的末尾指令。

### 2. 首次优化与恢复提示使用不同的输出范围

续写提示前面要求只输出后缀，但共享system prompt、章节任务描述、事实恢复和完整性恢复仍要求输出完整章节。这使模型需要在互相冲突的指令中选择，容易改动已有正文或重复开头；重试还可能重新引入同样冲突。

修复：续写的system prompt、任务描述、最终指令、事实恢复、截断恢复统一只返回完整新增后缀。受保护前缀继续提供上下文，由主程序拼接；replace仍返回完整章节。

### 3. 校验、提取和拼接对换行的处理不一致

前缀校验允许CRLF/LF差异，但后缀提取和合并按原始字符串比较。一个完整返回值通过校验后，仍可能被当成只有后缀，再拼一次原文。另一种情况是原文后直接接新句子而没有换行，被误判成改写前缀。

修复：比较和提取时统一换行；保存时保留作者前缀原有字节；完整前缀后直接接新文字也正确识别。新增集成测试实际核对保存文件，避免仅校验辅助函数。

### 4. 重试成功记录早于输出校验

模型只要返回candidate，原实现就在trace写成功；随后前缀/整章回声检查仍可能拒绝它。该问题在上述历史trace中有直接证据。

修复：先校验和合并，再写`succeeded`、`retryFailureKind`和candidateId。

### 5. 优化失败后将初稿重新标为优化稿

当前代码在前缀改写或整章回声重试失败后，曾复制Agentic候选并标成`editorial_amplified`继续进入保存；故事保持重试及最终恢复中也有同类分支。这违反“Agentic初稿不得直接交付”的项目规则，并不代表风格优化成功。

修复：物理删除这些伪装成功分支。定向恢复仍有界执行；失败耗尽则结构化阻断，不保存未通过优化的章节。
