# NovelOS M1 盲测协议

## 目的

盲测是 M1 验收 **Go 决策的手动门**。自动化 eval harness 只能产出 Go/Hold/No-Go 信号，Go 需人工盲测确认文学质量无明显负收益。

## 盲测原则

1. **匿名**：评审者不知道哪个是 B1（one_shot_raw）、B2（agentic_raw）、B3（verified_agentic_raw）。
2. **配对比较**：同一 fixture 的 3 条 baseline 候选匿名打乱后呈现，评审者做 A/B/C 相对比较。
3. **维度评分**：按 5 个维度评分（1-5 分），不做整体排名。
4. **负收益检测**：如果 B2/B3 在任何维度比 B1 差 ≥ 1 分，标记为「负收益风险」。
5. **不阻塞实现**：盲测只影响 Go 决策，不影响 Hold/No-Go（自动化指标已决定）。

## 5 个评审维度

| 维度 | 说明 | 评分标准 |
|------|------|---------|
| 事实正确性 | 候选是否引用了正确的历史事实、无知识边界违规 | 5=完全正确 / 3=有小瑕疵 / 1=严重错误 |
| 连续性 | 时间/空间/角色位置是否与前章一致 | 5=完全一致 / 3=有小矛盾 / 1=严重断裂 |
| 文学声音 | 句式节奏、留白、语言质感是否自然 | 5=声音鲜明 / 3=中性 / 1=AI 腔/翻译腔 |
| 情节推进 | 是否有效推进本章意图，无冗余/拖沓 | 5=推进有力 / 3=有推进但拖沓 / 1=停滞 |
| 读者体验 | 作为读者是否愿意继续读下去 | 5=强烈想读下章 / 3=中性 / 1=想弃书 |

## 盲测流程

### Step 1：准备盲测包

自动化 harness 产出盲测包目录 `reports/blind-test/`：

```
reports/blind-test/
├── F1-historical-fact/
│   ├── candidate-A.md    # 匿名候选（随机打乱 B1/B2/B3）
│   ├── candidate-B.md
│   ├── candidate-C.md
│   └── context.md         # 本章意图 + 前章摘要（不含哪个是哪条 baseline）
├── F2-knowledge-boundary/
│   └── ...
└── mapping.csv            # 盲测结束后解封，记录 A/B/C 对应哪条 baseline
```

候选文件**不含**任何标识 baseline 来源的信息（无 agentic_raw / one_shot_raw 字样、无 trajectory、无 tool events）。

### Step 2：评审

每个评审者独立完成所有 fixture 的盲测：

1. 阅读 `context.md`（本章意图 + 前章摘要）
2. 阅读三个匿名候选 A/B/C
3. 按 5 维度各打 1-5 分
4. 记录「最偏好」和「最不偏好」的候选
5. 如果某候选在事实正确性或连续性得 1 分，标记为「硬伤」

### Step 3：解封与统计

解封 `mapping.csv`，统计：

| 指标 | 计算 |
|------|------|
| B2 vs B1 平均分差 | avg(B2 总分) - avg(B1 总分) |
| B3 vs B2 平均分差 | avg(B3 总分) - avg(B2 总分) |
| B2 负收益率 | B2 总分 < B1 总分的 fixture 比例 |
| B3 负收益率 | B3 总分 < B2 总分的 fixture 比例 |
| 事实硬伤率 | 各 baseline 出现事实 1 分的 fixture 比例 |

### Step 4：Go 决策

**Go 条件**（全部满足）：
- 自动化 harness 产出 Go 建议
- B2 vs B1 平均分差 ≥ 0（检索不损伤文学质量）
- B3 vs B2 平均分差 ≥ 0（verifier 不损伤文学质量）
- B2/B3 事实硬伤率 ≤ B1 事实硬伤率
- 无评审者报告「明显负收益」

**Hold 条件**（任一满足）：
- 自动化 harness 产出 Hold
- B2 vs B1 或 B3 vs B2 平均分差 < 0（但有 fixture 正收益）
- 评审者报告「部分负收益但可优化」

**No-Go 条件**（任一满足）：
- 自动化 harness 产出 No-Go
- B2 vs B1 平均分差 < -1（明显负收益）
- B2/B3 事实硬伤率 > B1 事实硬伤率（检索/验证引入更多事实错误）

## 评审者要求

- 至少 2 名评审者独立完成
- 评审者不得参与 fixture 构造或 harness 开发（避免确认偏差）
- 评审者可以是项目维护者，但必须在盲测前不查看 mapping.csv

## 盲测记录

盲测完成后，评审记录写入 `reports/blind-test-results.md`：

```markdown
# NovelOS M1 盲测结果

## 评审者
- 评审者 A：（姓名）
- 评审者 B：（姓名）

## 统计
| 指标 | 值 |
|------|------|
| B2 vs B1 平均分差 | +0.X |
| B3 vs B2 平均分差 | +0.X |
| B2 负收益率 | X/6 |
| B3 负收益率 | X/6 |

## Go/Hold/No-Go 决策
（基于上述统计和 Go 条件判断）

## 评审者备注
（可选：对检索/验证能力的定性评价）
```

## 注意事项

- **M1 阶段盲测是可选的**：如果自动化 harness 产出 Hold 或 No-Go，无需盲测（自动化指标已决定）。
- **盲测只在自动化产出 Go 时必需**：作为 Go 决策的手动门。
- **盲测不阻塞实现完成**：Step 6 的交付物是自动化 harness + 盲测协议，不是盲测结果本身。
- **fixture 质量决定盲测说服力**：6 fixture 作为代码评审重点，确保对抗样本真实。
