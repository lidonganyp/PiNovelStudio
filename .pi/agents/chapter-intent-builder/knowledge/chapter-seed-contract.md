# 章节契约手册（Chapter Seed Contract）

> 本文件是 `chapter-intent-builder` 的唯一知识库，合并原「章节契约 + Seed 质量评分卡」两份资料，已去重。

## 1. Seed 可生长性判定

写前输入必须能回答下面四项，缺一即 `status: blocked`：

| 项目 | 合格标准 |
|---|---|
| 方向 | 本章要去哪里（一句可判定的目标） |
| 冲突 | 谁阻止谁、代价是什么 |
| 状态 | 主角当前位置/能力/已知信息 |
| 承诺 | 本章必须触碰的 `PROMISE-*`（第 1 章无前章状态时写"不适用"） |

第 1 章且无前章 `narrative-state` 时，"承诺"项允许显式标注"不适用"，不视为缺项。

## 2. 意图收敛

- 主意图：**1 条**（这章最想让读者获得什么）
- 次意图：**≤2 条**
- 关键词：3–6 个，用于检索与自查

**反例**："本章要推进主线、揭示身世、加感情戏、埋两个伏笔、展示新能力"——意图过载，正文会每项只写一点。

**收敛话术**：

```
作者说：我想写他去找师父，顺便揭开一点身世，再和女主有点暧昧。
收敛为：
- 主意图：主角第一次主动追查师门线索
- 次意图：揭开"笔记少一页"的部分真相
- 关键词：师门 / 笔记 / 主动
- 剔除：暧昧（本章无承载位置，移到下一章）
```

## 3. 必需项布尔判定（先判真假，再谈分数）

结构落盘前必须逐项回答 true / false，**任一必需项为 false 即 `status: blocked`**，不允许用总分掩盖：

| 必需项 | 判定问题 | true 的判据 |
|---|---|---|
| 方向 | 本章要去哪里，能否一句话判定 | 存在一句可验证的目标 |
| 冲突 | 谁阻止谁、代价是什么 | 能指名阻止者与代价 |
| 状态 | 主角位置/能力/已知信息是否齐备 | 三项齐全且与状态摘要一致 |
| 意图 | 是否存在且只有 1 条主意图 | 主意图唯一，次意图 ≤2 |
| 硬事实 | 是否至少引用 1 条已登记 `FACT-*` / `OOC-*` | 引用 ID 在 canon/人物卡中真实存在 |
| 章末目标 | 读者状态 / 主角位置 / 新问题三项是否可判定 | 三项各一句且可验证 |
| 承诺 | 本章必须触碰的 `PROMISE-*` 是否已明确 | 有前章状态时必须列出；新书写"不适用"并说明理由 |

**评分只作建议**：可以对方向清晰度、冲突具体度等做 0–2 分的自评，用于给作者排序改进优先级；评分**不得**替代必需项判定，也不得因为"总分高"而放过一个 false 的必需项。

**新书特别规则**：第 1 章且无前章 `narrative-state` 时，承诺项判定为"不适用"（不算 false），但必须在契约中显式写 `承诺：不适用（第 1 章无前章状态）`，且禁止编造任何 `PROMISE-*` ID。

## 4. 硬事实引用规则

```markdown
| 类型 | ID | 内容 | 违反后果 |
|---|---|---|---|
| FACT | FACT-03 | 复苏之眼每日唤醒一次 | FactGuard 硬阻断 |
| OOC | OOC-02 | 林默不会出卖同伴 | 连续性审校退回 |
```

- 只能引用 canon 与人物卡中**已存在**的 ID。
- 需要新设定时，先回到 `world-builder` 落 canon，再引用。

## 5. 章末目标写法

| 合格 | 不合格 |
|---|---|
| 读者应意识到"苏雨一直在隐瞒" | 读者会感到震撼 |
| 主角从被动挨打转为主动布局 | 主角成长了 |
| 留下"笔记为何少一页"的新问题 | 留悬念 |

## 6. 事件级契约（可选，仅在作者已给出事件顺序时）

作者明确给出本章事件顺序时，可追加事件段；**作者没给就不写**，禁止为了让契约"完整"编造事件。

```markdown
## 事件
### 事件 1：<标题>
- **参与角色**：<只用人物卡里已存在的角色>
- **必须包含**：<本事件不可省略的动作或信息>
- **内容摘要**：<一句话说清发生了什么>
- **事件结果**：<事件结束时状态发生了什么改变>
```

> 章节标题固定为 `## 事件`，每个事件用 `### 事件 N：<标题>`；`###` 层级不可改成 `##`，否则会被当成并列小节而解析不到事件。

事件级契约的三条硬要求：

- **顺序即承诺**：事件顺序必须与作者口径一致；需要调整时先向作者确认，不自行重排。
- **角色不得虚构**：`参与角色` 必须能在人物卡中找到；需要新角色时先回 `character-designer`。
- **结果可判定**：`事件结果` 必须能被下一事件或章末目标检验，禁止写"气氛变好了"。

本段是**可选**段；与章级契约冲突时以章级契约（意图 / 硬事实 / 章末目标）为准。

## 7. 不可指定项（表达自由归正文模型）

⛔ 不写：开头方式、感官描写、词汇选择、句式结构、修辞手法、对白分配、段落节奏、具体场景布置。

## 8. 常见失败样本

| 失败样本 | 问题 | 修法 |
|---|---|---|
| "写第 10 章" | 没有任何意图 | 先问"这一章要达成什么" |
| "推进主线，揭示身世，加感情戏" | 意图过载（3 主意图） | 压成 1 主 + 1 次 |
| "主角变强了" | 不可判定 | 改为"从被动变为主动布局" |
| "让他面对内心" | 不可观察 | 改为"他做出一个不可逆选择" |
| "参考第 3 章的写法" | 指向表达而非目标 | 删掉，表达归正文模型 |

## 9. 交付检查

工具入参摘要（交付时必附）：

```markdown
- workspaceId: <id>
- chapterNumber: <n>
- writerModel: <gemini31|claude|省略>
- preflight: pass | blocked（blocked 时附 blockingItems 原样）
```

自检清单：

- [ ] `workspaceId` / `chapterNumber` 明确
- [ ] 必需项布尔判定全部为 true（"承诺"项允许显式"不适用"）
- [ ] `novel_preflight_workspace` 已通过（或已列出 `blockingItems`）
- [ ] 硬事实只引用已有 `FACT-*` / `OOC-*`
- [ ] 事件级契约仅在作者已给出事件顺序时出现，且未虚构角色与结果
- [ ] 未指定任何表达层内容（开头/词汇/句式/对白分配）
- [ ] 契约不作为最终产物展示给作者
